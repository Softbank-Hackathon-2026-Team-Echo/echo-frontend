# 손으로 돌리는 전체 유저 플로우

배포 전후에 사람이 직접 눌러 보는 순서다. 위에서 아래로 한 번 돌면 처음 쓰는 사람의 흐름과 시연 흐름을 모두 지난다.

## 어디서 돌리나

| 곳 | 주소 | 쓰임 |
|---|---|---|
| 로컬 | `http://localhost:5173/o/echo-demo` (`pnpm dev` + 가짜 API) | 화면 · 문구 · 눌렀을 때의 흐름. 값은 가짜다 |
| 운영 | `https://app.echoport.uk` | 실제 배포 · 변수 · 이전. PR 을 머지해 Cloudflare 배포가 끝난 뒤에 된다. 운영 API 는 이 주소만 받는다 |

## 시작 전에

- 표시 `⚠ 공지` 단계는 실제 트래픽이나 앱을 움직인다. 팀 채널에 먼저 알린다
- 변수에는 가짜 값만 넣는다. 화면 녹화 · 스크린샷에 값이 나오면 안 된다
- 운영 시험용 서비스를 따로 쓴다. `demo` 는 시연 서비스라 변수를 건드리지 않는다
- 트래픽 비율과 DB 쓰기 담당은 조직 전체가 공유한다. 한 서비스를 이전하면 모두 움직인다

## 1. 처음 들어오기

- [ ] `/` 로그인 전이면 소개, 로그인 뒤면 조직으로 간다
- [ ] 조직 대시보드에 서비스 카드 · 환경 · 최근 활동 · 비용이 보인다
- [ ] 상단 바에 월 추정 비용이 있고, 누르면 단가표가 열린다
- [ ] 서비스 카드를 누르면 그 서비스의 개요로 간다

## 2. 서비스 등록과 첫 배포 ⚠ 공지

- [ ] 서비스 목록의 행 어디를 눌러도 상세로 간다
- [ ] 새 서비스 배포에 저장소 주소를 넣으면 이름이 채워진다
- [ ] 고급 설정이 접혀 있고 "배포 전에 확인" 이 보인다
- [ ] 등록하면 배포 창이 바로 열린다
- [ ] 배포를 시작하면 단계 · 시간 · 로그가 움직인다

## 3. 배포 실패 → 원인 → 고치기 ⚠ 공지

`DATABASE_URL` 이 필요한 앱을 변수 없이 배포해 실패시킨다.

- [ ] 실패 단계 아래에 원인 문장이 붙는다. 뒤 단계는 시작 전으로 남는다
- [ ] 첫 배포면 "이전 버전이 계속 실행 중" 이 아니라 실행 중인 버전이 없다고 나온다
- [ ] "AI 로 원인 보기" 를 누르면 분류 · 근거 · 고치기 버튼이 나오고 `simulated` 배지가 있다
- [ ] 고치기 버튼이 변수 탭 · 설정 · 빌드 로그 · 롤백 · 다시 배포 중 맞는 곳으로 간다
- [ ] 로그 검색 · 내려받기가 된다
- [ ] 배포 탭의 환경 카드는 지금 버전을 유지하고, 실패는 한 줄로 나온다

## 4. 환경 변수 ⚠ 공지 (적용 단계)

- [ ] 빈 화면의 첫 버튼이 `.env` 붙여넣기다
- [ ] 붙여 넣으면 키가 미리 보이고 값은 가려진다. `PORT` 는 예약 이름 경고가 나온다
- [ ] 넣을 환경을 체크로 고른다
- [ ] 저장하면 키 × 환경 표에 버전과 `다시 배포해야 반영` 이 나온다
- [ ] 상단 띠에 변경 수와 키 이름이 나오고, 다른 탭으로 가도 남는다
- [ ] 자세히에 재배포될 환경 · 커밋 · 버전이 나오고 값은 없다
- [ ] 변경 배포 한 번으로 배포 탭으로 가고, 끝나면 띠가 사라진다
- [ ] 서비스 중 환경에 있는 키가 다른 환경에 없으면 경고가 뜨고 그 칸에서 바로 넣는다
- [ ] 새 변수 한 줄 입력, 값 바꾸기, 삭제(이름 입력)가 된다

## 5. 지표 · 활동 · 설정

- [ ] 개요에 이 서비스의 KPI · 토폴로지가 보인다. 서비스를 바꾸면 값이 바뀐다
- [ ] 지표 탭에서 15m · 1h · 6h 를 바꾸고, 배포 · 이전 시점 점선을 본다
- [ ] 활동 서랍의 배포 · 이전 줄을 누르면 그 화면으로 간다
- [ ] 설정 탭에 저장소 · 헬스 체크 · 포트 · 환경별 값 · 삭제가 있다
- [ ] 롤백은 확인 창이 범위를 적고, 눌러야 시작한다 ⚠ 공지

## 6. 재난 없는 이전 ⚠ 공지

- [ ] 이전 탭에서 환경별 준비 상태와 빠진 키를 본다
- [ ] 예비가 없으면 "먼저 배포" 로 안내한다
- [ ] 이전 계획 만들기에서 AI 사전 점검으로 간다. 이 버튼이 실제 점검을 만든다
- [ ] 패치 카드에 반영 결과 · 실패 코드 · 브랜치가 나온다
- [ ] 계획 화면에 전체 이동 안내가 있고, 승인하면 실행 화면으로 간다
- [ ] 10 → 50 → 100% 와 결과를 본다

## 7. 재난 · 긴급 이전 · 복귀 ⚠ 공지 (시연 전체)

- [ ] 도착 환경 사전 점검이 24시간 안에 있다. 없으면 먼저 돌린다
- [ ] 재난 다이얼로그에서 실제 이전이 시작된다는 안내를 체크해야 보낼 수 있다
- [ ] 서비스 개요에서 상태 알약 · 토폴로지 · A·B 그래프가 움직인다
- [ ] 재난 종료 뒤 복귀를 시작한다. 복귀 대상 사전 점검이 없으면 승인 때 C-AI-1 로 막히고, 그 줄의 링크로 점검을 돌린다
- [ ] 감사 로그에 재난 · 계획 · 승인 · 종료가 남는다

## 8. 화면 전체 점검

경로를 고정해 한 번씩 본다: 대시보드 · 서비스 목록 · 서비스 탭 6개 · 배포 진행 · 대피 · 사전 점검 · 계획 · 이전 목록 · 이전 실행 · 보안 · 감사 로그 · 설정 · 리모컨(`/o/:slug/remote`) · 온보딩.

- [ ] 사용자 메뉴에서 테마 라이트 · 다크 · projector
- [ ] 언어 한국어 · 일본어 · 영어. 번역이 빠져 영어가 섞이지 않는가
- [ ] 너비 1440 · 960(반분할) · 휴대폰(리모컨)
- [ ] 뷰어 · 개발자 · 어드민. 권한 없는 버튼이 비활성 + 이유로 나오는가
- [ ] 비어 있는 상태 · 로딩 · 오류 상태
- [ ] 키보드 Tab 으로 다이얼로그 · 메뉴를 쓸 수 있는가
- [ ] 브라우저 콘솔 빨간 오류, Sentry 새 이슈

## 찾은 문제 적는 법

화면 주소 · 역할 · 테마 · 언어 · 한 일 · 기대한 것 · 실제 결과 · 스크린샷 · 시각을 적는다. API 오류면 토스트의 요청 id 를 같이 적는다.
