# 시연 대본 (초안)

- **기준**: 이슈 #11, echo-frontend #51 지민님 답변, Figma 「S01 · split screen 1920」 장면 1~5
- **시간**: 최종 발표 5분 안(완료 기준). 리허설에서 재서 고친다
- **화면**: 왼쪽 960 EchoPort(projector 테마), 오른쪽 960 관리 대상 앱
- **조직 · 서비스**: `echo-demo` · `demo`, 대표 주소 `demo-y6cz3jrc.echoport.uk`
- 사람 이름이 정해지지 않은 칸은 리허설 때 채운다

## 시작 전 확인

- [ ] 서비스 `demo` 가 AWS 도쿄 100%, GCP 서울 · 온프레는 예비
- [ ] 세 환경 모두 연결됨
- [ ] 진행 중 배포 · 이전 없음, 재난 시뮬레이션 없음
- [ ] 진행자 역할이 Developer 이상, 혼자 승인하면 본인 승인 설정 켜짐
- [ ] 시연 언어 선택, 테마 projector
- [ ] DB 쓰기 전환 담당(동옥님)이 대기 중, 복제가 A → B 방향으로 정상
- [ ] 관리 대상 앱 쓰기 시작 시점을 정함(장부를 비우는 기능이 없다)
- [ ] 운영 작업을 시작한다고 슬랙에 알림

## 순서

| 장면 | 하는 일 | 보여 줄 것 |
|---|---|---|
| 1. 평상시 | 대시보드와 앱을 나란히 띄운다 | 토폴로지에서 AWS 100%, 예비 2곳 |
| 2. 재난 | 상단 재난 시뮬레이션에서 도쿄 근처 M7.2 시작 | 영향 반경, 위험 표시, `simulated` 배지 |
| 3. 대피 준비 | 대피에서 GCP 서울을 고르고 AI 사전 점검, 계획 확인 | 후보 점수, 패치 승인, 보안 비교 (`simulated`) |
| 4. 이전 | 계획 승인 | 10 → 50 → 100%, 대시보드 비율, 앱 응답 서버 변화 |
| 5. 결과 | 완료 카드에서 결과 보기 | 걸린 시간, 실패 요청 |
| 6. DB 쓰기 전환 | 동옥님이 컷오버 실행 | 쓰기 정지 약 8초, 누락 · 중복 0 |
| 7. 복귀 | End simulation → Start failback → 승인 | Failback 제목, 100% 복귀 |

**순서를 바꾸지 않는다.** 재난이 끝나지 않으면 복귀가 잠기고, DB 쓰기 전환 전에 복귀하면 데이터 확인에서 실패하고 롤백된다.

## 말할 때 주의

- 재난 버튼은 운영 API 다. 재난은 시뮬레이션이지만 M7.0 이상이면 실제 이전이 시작된다. 도착 환경 사전 점검이 24시간 안에 없으면 게이트가 멈춰 둔다
- 대피 후보, 보안 비교(Compare · E01-3)는 지금 시뮬레이션이다. 배지를 가리키며 밝힌다
- AI 사전 점검은 운영 API 다. 러너가 돌고 있어야 끝나고, 없으면 "러너를 기다리는 중"에 머문다. 시연 전에 러너를 켠다
- 실패 요청 숫자를 보이려면 이전 중에 데모 앱으로 요청을 흘린다. 요청이 없으면 헬스 체크 통과로 나온다
- 쓰기 정지 8초를 "무중단"이라고 말하지 않는다. 무중단은 트래픽 이전 기준이다
- "실패 요청 0" 은 앱 이전 값이다. DB 리허설에서는 쓰기 166건 중 5건이 클라이언트 타임아웃이었고 그중 4건은 DB에 반영됐다(누락 0)
- 숫자는 리허설에서 잰 값만 말한다. 재측정 전 값은 데이터 확인이 가짜였던 때의 값이다

## 실패할 때

| 상황 | 대응 |
|---|---|
| 이전 중 이상 | 화면의 Roll back. 출발 100% 로 돌아가는지 보여 주고 롤백 시연으로 넘긴다 |
| 자동 롤백 | 결과 화면의 실패 이유를 보여 주고 계획을 다시 만든다 |
| 복귀가 데이터 확인에서 실패 | DB 쓰기 전환이 끝났는지 확인한다. 화면에 같은 안내가 나온다 |
| 운영 API 불통 | 정하지 않았다. 녹화 영상 등 수동 대체 경로를 리허설 전에 정한다(NFR-14) |
