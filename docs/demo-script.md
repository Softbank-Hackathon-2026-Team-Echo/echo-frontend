## 순서

| 장면 | 시간(목표) | 하는 일 | 보여 줄 것 |
|---|---|---|---|
| 1. 평상시 | 30초 | 서비스 Overview(`/o/:slug/services/:id`)와 앱을 나란히 띄운다 | 토폴로지에서 AWS 100%, 예비 2곳, 앱 응답 환경 도쿄 |
| 2. 재난 | 20초 | 휴대폰에서 도쿄 근처 M7.2 → 재난 발생 → 한 번 더 누른다 | Overview 재난 칸, 영향 반경 302km, `simulated` 배지, 긴급 이전 시작 |
| 3. 이전 | 1분 40초 | 자동으로 10 → 50 → 100%. 도는 동안 장면 4 를 말한다 | 상단 "대피 중 N%", 토폴로지 비율, 앱 응답 환경이 서울로 바뀜 |
| 4. 안전장치 | (3 안에서) | 보안 탭과 사전 점검 결과를 보이고 서비스 Overview 로 돌아온다 | 게이트가 승인을 판단했다는 것, 예외와 사유, AI 사전 점검 결과 |
| 5. DB 쓰기 전환 | 30초 | 완료 카드 뒤 컷오버 담당이 `cutover.sh` 실행 | 이전 결과 화면에 쓰기 정지 · 누락 · 중복이 나타남 |
| 6. 재난 종료 · 복귀 | 1분 40초 | 시뮬레이션 종료 → 복귀 시작 → 계획 만들기 → 승인 | 재난 중 잠겼던 복귀가 풀림, 복귀 제목, 100% 복귀 |
| 7. 감사 | 20초 | 감사 로그를 연다 | 재난, 계획, 승인, 이전 종료가 누가 · 언제로 남음 |

합계 약 4분 40초는 요청이 없을 때 값이다(단계마다 30초를 기다린다). 11/4 진입점에 초당 50건 부하를 걸었을 때는 이전 9초, 복귀 13초였다(#51). 그만큼 짧으면 장면 4 를 이전 뒤로 옮겨야 하니 부하를 건 리허설로 다시 잰다.

**순서를 바꾸지 않는다.**

- 재난이 끝나지 않으면 복귀가 잠긴다.
- 컷오버는 이전이 끝난 뒤에 한다. 이전 도중이면 쓰기 정지가 오류율에 걸려 자동 롤백될 수 있다.
- 컷오버를 했으면 시연 뒤 `rollback.sh` 로 A 를 주 DB 로 돌린다. 다음 시연이 같은 상태에서 시작한다.

**컷오버를 뺄 때**: 장면 5 없이 복귀해도 된다(echo-was #73, 11/5 운영 확인). 그때 결과 화면의 쓰기 정지 · 누락 · 중복은 `—` 로 남는다.

## 말할 때 주의

- 재난은 시뮬레이션이지만 **이전은 실제**다. 이 구분을 처음에 말한다
- 쓰기 정지를 "무중단"이라고 말하지 않는다. 무중단은 트래픽 이전 기준이다
- 쓰기 정지는 부하 없이 5~9초였다(5.36 · 5.56 · 5.82 · 8.53초). 복귀 쪽 롤백은 6.76 · 7.12 · 9.77초다
- "실패 요청 0" 은 요청으로 판정했을 때만 말한다. 11/5 시험은 판정 1건이라 성과로 말할 수 없다
- DB 리허설에서는 쓰기 166건 중 5건이 클라이언트 타임아웃이었고 그중 4건은 DB 에 반영됐다(누락 0)
- 숫자는 리허설에서 잰 값만 말한다. 재측정 전 값은 데이터 확인이 가짜였던 때의 값이다
- 지금 시뮬레이션은 대피 후보 점수, 보안 비교(Compare · E01-3)다. 배지를 가리키며 밝힌다. 재난으로 시작하는 흐름에서는 이 화면을 쓰지 않는다
- 매트릭스의 `알 수 없음` 은 증거를 아직 모으지 못한 칸이다. 통과라고 말하지 않는다. 서버가 아직 예외를 매트릭스에 반영하지 않아 예외가 걸린 칸도 `알 수 없음` 이다
- AI 사전 점검이 규칙 비교뿐이면 "AI 검토 없음 · 규칙 비교만" 이라고 나온다. AI 가 고쳤다고 말하지 않는다

## 실패할 때

| 상황 | 대응 |
|---|---|
| 재난을 냈는데 승인 대기로 멈춤 | 재난 칸의 이유를 본다. 게이트면 이유를 보여 주고 사전 점검을 돌린 뒤 승인한다 |
| 이전 중 이상 | 이전 화면의 롤백. 출발 100% 로 돌아가는지 보여 주고 롤백 시연으로 넘긴다 |
| 자동 롤백 | 결과 화면의 실패 이유를 보여 주고 계획을 다시 만든다 |
| 러너 대기에서 멈춤 | 시연 전 점검이 있으면 영향이 없다. 없으면 중지하고 게이트 차단 화면을 보여 준다 |
| 휴대폰이 안 됨 | 상단 재난 시뮬레이션 버튼으로 낸다. 같은 API 다 |
| 운영 API 불통 | 위 "팀이 정할 것" 참고 |
